# 모바일 개선 및 반복 점검

## 사용자 화면

- 회원가입, 로그인, 신청, 정보 저장 등 일반 POST 폼에 처리 중 안내와 반복 제출 방지를 적용한다. 관리자 저장 버튼의 이름과 값을 보존하므로 저장 후 계속 편집 등 Django 동작이 유지된다.
- 브라우저/페이지 검증에서 제출을 취소하면 잠그지 않는다. 이전 페이지로 돌아오면 처리 상태를 해제한다. 네트워크 요청의 자동 재전송은 하지 않는다.
- 관리자 추가·편집 폼은 입력 내용이 바뀐 상태에서 페이지를 떠나면 브라우저 확인 안내를 요청한다. 비밀번호나 작성 내용을 저장소에 보관하지 않는다. 모바일 앱 강제 종료 등 브라우저가 안내 이벤트를 제공하지 않는 경우까지 보장하지 않는다.
- 폭 1120px 이하 관리자 목록은 카드 보기로 시작한다. 원래 입력칸·선택 체크박스를 그대로 사용한다. 주요 항목과 편집 가능한 항목은 바로 표시하고 나머지는 '추가 정보 펼치기'로 확인한다.
- '표 보기'로 열 정렬과 전체 열 비교를 할 수 있다. 보기 전환이나 화면 회전으로 작성 중인 값이나 선택 상태가 사라지지 않는다. JavaScript가 꺼져 있으면 기존 표로 동작한다.
- 관리자 관련 객체 버튼·권한 이동 버튼의 터치 영역을 확대했다. 긴 URL과 강의명이 포함된 공지 목록도 줄바꿈한다.

## 자동 검사 실행

```sh
pip install -r requirements.txt
npm ci
npx playwright install chromium webkit
npm run test:js
npm run test:mobile
```

Linux에서는 브라우저 설치에 `npx playwright install --with-deps chromium webkit`를 사용한다.

`config.browser_test_settings`는 DB·자료 폴더를 `.browser-tests/`로 고정하고 외부 메일을 차단한다. 운영 데이터나 계정을 사용하지 않는다. 브라우저 테스트는 자체 서버(127.0.0.1:8766)를 실행하며 이미 실행 중인 서버를 임의로 재사용하지 않는다.

Chromium과 WebKit에서 세로 320/390/412px, 가로 915px, 글자 200% 조건으로 공개·수강생·관리자 화면을 확인한다. 전체 문서 넘침, 일반 본문 잘림, 하단 메뉴 겹침, JavaScript 오류, 인증 리다이렉트를 검사한다. 별도로 카드/표 전환·선택·편집값 유지, 느린 POST 중복 제출, 서버 검증 오류, 저장 전 이동, JavaScript 비활성 상태를 확인한다.

GitHub Actions의 `Mobile regression checks`는 push/PR 때 서버 테스트, JavaScript 테스트, 모바일 검사를 실행한다. 실패하면 보고서·스크린샷·추적 파일을 14일 보관한다. 배포할 커밋의 검사가 통과했는지 확인한 뒤 배포한다. 저장소의 필수 검사/브랜치 보호 설정은 이 워크플로 파일과 별개다.

`deploy/onedu-remote.ps1 -Action deploy`도 서버에 소스를 보내기 전에 모바일 검사를 자동 실행하고 실패하면 배포를 중단한다. 따라서 배포 PC에도 위의 Python/Node 의존성과 브라우저 설치가 필요하다. 추적 중인 소스가 커밋되지 않았다면 배포하지 않으며, `-AllowDirty`는 미추적 개인 문서가 있는 경우에 사용할 수 있다.

## 실제 기기에서 남은 확인

이 작업 환경에 연결된 휴대폰이 없어 아래 항목을 실제 기기에서 통과했다고 표시하지 않는다. WebKit 검사는 실제 iOS Safari 및 카카오톡 내장 브라우저 검사와 구분한다.

| 환경 | 확인할 동작 |
| --- | --- |
| Android Chrome, iPhone Safari | 로그인 → 강의실 → 영상 재생 → 가로 회전 → 전체화면 → 다른 앱 사용 후 복귀 |
| 두 운영체제의 카카오톡 내장 브라우저 | 공유 링크 진입, 로그인 유지, PDF 열기, 외부 브라우저 안내 |
| 휴대폰 키보드/홈 화면 아이콘 | 내 정보 입력칸·저장 버튼 접근, 키보드 닫기, 홈 화면 아이콘에서 다시 접속 |

## 운영 백업 확인 — 2026-09-18 00시대 KST

- 허용된 원격 `backup-check`로 최근 DB 백업 파일을 확인했다. 출력의 최신 파일은 `onedu_20260917_140115.sql`(약 229KB)이며, 그 외 일일 03:20 백업도 존재했다. 파일 존재 확인이며 복구 성공 확인은 아니다.
- 공개 자료 및 비공개 비영상 자료 백업 목록에는 파일이 출력되지 않았다. 원인이 설정, 권한, 백업 실행 실패 중 무엇인지는 아직 확인되지 않았다.
- 운영 자료 디렉터리는 공개 자료 약 11MB, 비공개 자료 약 15GB로 출력됐다.
- Synology Hyper Backup 패키지 설치는 확인했다. ONEDU 영상 폴더가 실제 작업에 포함되는지, 외부 저장소 사본이 있는지, 최근 성공 시각은 확인하지 못했다.
- 현재 SSH 계정은 제한된 `onedu-ops` 작업만 비밀번호 없이 실행할 수 있다. 백업 디렉터리 직접 접근과 Docker 접근이 거부되어 파일 열기·격리 복구 시험을 실행하지 않았다. 운영 DB를 덮어쓰거나 관리자 권한 설정을 변경하지 않았다.

DSM 관리 권한으로 확인할 순서:

1. Hyper Backup 작업에 `data/private_media/lesson_videos`, `lesson_hls`, 비영상 교재, 공개 자료가 포함되는지 확인한다. 다른 저장 장치의 사본과 최근 성공 기록을 확인한다.
2. 영상 원본 1개와 PDF 1개를 **별도 임시 폴더**에 복원해 원본과 크기·해시를 비교하고 재생/열기를 확인한다.
3. 최신 DB 덤프를 별도 PostgreSQL 16 시험 인스턴스에 복원한다. 운영 DB의 주소·계정을 사용하지 않는다. 회원·강의·수강·진도 테이블의 관계와 표본 기록을 확인한다.
4. 앱의 `ONEDU_BACKUP_INCLUDE_PUBLIC_MEDIA`, `ONEDU_BACKUP_INCLUDE_PRIVATE_NONVIDEO` 설정과 일일 백업 작업 로그를 확인해 자료 백업 목록이 비어 있는 이유를 해소한다.
5. 성공한 백업 시각, 복원 시각, 대상 파일, 해시 비교와 DB 검사 결과를 기록한다.
